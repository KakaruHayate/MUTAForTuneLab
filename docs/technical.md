# MUTA for TuneLab — 技术说明

面向技术交流：讲清楚这个插件**是怎么把 MUTA 的歌声合成接进 TuneLab 的**、每一层为什么这样设计、
以及哪些地方踩过坑。不写开发过程，也不写待办。

---

## 0. 一句话

MUTA 的歌声 = **一个共享的中文 HTS 声学模型** + **每个声库一份录音参数（bank）**；
本插件复刻前者、读取后者，用世界级开源声码器 worldline 出声，并把它包装成 TuneLab 的
voice 引擎（一个 part 一条合成会话）。

它不是重新训练，也不是采样拼接：**模型给时长与频谱骨架，bank 决定音色，声码器决定质感**。

---

## 1. 为什么是这个结构

MUTA 的 `.voice` 是标准 HTS 声学模型，`.inf`/`.bnk` 是逐段录音的 MGC/BAP 参数。
原版引擎的分工是：

```text
歌词 ──► 音素 ──► HTS 全上下文标签 ──► HTS 模型 ──► 时长 / MGC / LF0 / BAP
                                                        │
                                        bank 用真实录音替换 MGC / BAP
                                                        │
                                              F0 弯到谱面音高 ──► 声码器
```

插件照这个分工实现。三个 MUTA 声库（嫣汐 / 琥珀 / 未央）的 `.voice` 字节完全相同，
**差异全在 bank**——所以"换声库"在实现上就是换 `.inf`/`.bnk`，模型可以缓存复用。

---

## 2. 宿主的契约面

TuneLab SDK 1.1 给 voice 插件两个接口：

| 接口 | 职责 |
|---|---|
| `IVoiceSynthesisEngine` | 扫描声源、声明参数（part 级 / note 级 / 音素级） |
| `IVoiceSynthesisSession` | 每个 part 一条：规划分块、渲染、发布产物（音频段、音素、音高回显、状态） |

驱动方式是"**peek 下一块 → commit 同一块**"：宿主先问下一块是什么，再让插件渲染它。
宿主可能在两者之间改数据，所以分块必须是**纯函数**，否则 peek/commit 会错位。

数据线程上只能读 `VoiceSynthesisSnapshot`（冻结的数据 + 曲线求值器），不能碰 live 视图。
曲线（`Pitch`、各自动化轨）在同步前缀里按块内帧时间**一次批量求值**，随快照带进 worker。

---

## 3. 数据：`.voice` / `.inf` / `.bnk`

| 文件 | 内容 | 读取方式 |
|---|---|---|
| `.voice` | HTS 声学模型（含 `MCP:ALPHA`、帧周期） | 整个加载，进程内按路径缓存 |
| `.inf` | 每段录音：左音素 / 当前音素 / 右音素 / 帧数 / 音高码 / bank 偏移与大小 | 启动时索引，常驻 |
| `.bnk` | 按 `.inf` 偏移取出的 float32：每段 MGC 50 维 + BAP 26 维 | **按需读取**，不整文件加载 |

单个声库约 94 MB，全量入内存不值得；bank 是按槽随机访问的，所以只读需要的段。

---

## 4. 两种语言，一条链

关键设计：**音色（bank）与语言（前端 + 标签方言）是两个正交轴**。

```text
              ┌─ 中文前端：拼音音节 ─► MUTA 标签 ─┐
bank（录音）──┤                                    ├─► HTS（对应模型）─► bank 替换
              └─ 日文前端：假名 ─► Sinsy 标签 ────┘
```

- 语言是 **part 属性**（`language = zh | ja`，默认 `zh`，**没有 auto**）。
  宿主在引擎之前就把歌词罗马化（汉字→拼音、假名→罗马字），`ni` 中文日文都成立，文本反推不可靠。
- 日文时序来自随包的 NIT SONG070 模型（`sinsy/voice/`），但它**只提供标签与时长**；
  日文的音色仍来自当前 bank。所以日文不需要额外声源。
- 切语言只换前端，选槽与音色不变。

日文的音素 → bank 音素映射是**运行时数据**（`ja-zh-phone-map.tsv`），改表不用重编。
表是按"试听"定稿的，例如 `e → ei`、`o → ou`、`kyo → k + iao`、`N → en`；
bank 里没有的组合由选槽算法按音类回退。

## 5. 合成链

### 5.1 标签

- 中文：`LabelBuilder` 生成 HTS 全上下文标签（音素、音节、词、音高、时值等字段）。
- 日文：`MusicXmlWriter` 把音符写成 MusicXML **文本**，以内存流交给 `muta_sinsy.dll`
  （Sinsy 的 reader 接受任意 `IReadableStream`，不落临时文件），取回全上下文标签。

一个必须记住的约束：**音符不能被小节线切开**。切分器原先对所有事件一视同仁，
一个长音被劈成两段、同歌词出现两次，Sinsy 就会把它唱两遍（实测：两音符乐句给出 6 个音素）。
现在小节长度覆盖整个块，休止可切、音符不可切。

### 5.2 声学模型

`muta_hts.dll` 包装 HTS engine，只导出需要的入口：加载、合成、读 MGC/LF0/BAP、状态时长、语速。
原生包装在合成期间用进程级全局状态，所以调用串行化。

### 5.3 录音层（bank）

有 `.bnk` 时，`BankRenderer` 用录音参数**整体替换**模型输出的 MGC/BAP，模型只保留 F0。
每个音符拆成"声母槽 + 韵母槽"，各选一段录音：

- 写入按目标帧数做三段伸缩（前缀/核心/后缀），元音与前一音符重叠处交叉淡化；
- **连音乘客不选槽**：`-`/`+` 没有自己的槽，链头的韵母槽按 `本音符 + 乘客帧数` 拉伸、
  覆盖整段；这样乘客处不会出现第二段录音的起音（MUTA 的 `IsDash → continue` 语义）；
- **换气音符**（`br` / `sp`）不参与选槽：中文标签给它一个 `sp` 停顿、日文谱面留空，
  它的声音来自 `.inf` finals（无 finals 的库用带通噪声），在声码器之后按相对电平混入；
- **声母长度取 MUTA 自己的定长表**（`LabelBuilder.ConsonantFrames`：
  `MinPhoneDuration`，tick/50000，再取 min(表值, 音符/2)），不用模型的
  state duration——后者比它长 50–80%，短音符上会把韵母挤没；这份帧数同时决定标签、bank 槽位
  和回传给宿主的音素，三者同源；
- 促音带来的 `cl` 不算进下一个音符的起音；闭锁（`cl`）显式跳过、保持静音，不落进
  "韵母没有录音"的回退分支（否则会唱出一个 `a`）。

### 5.4 选槽算法

`BankContext` 在 `.inf` 的音素组里按**音类加权**打分取最近项：

```text
score = 左上下文匹配 + 右上下文匹配 + 音类 + 音高距离 + 时长距离
```

同分取 `.inf` 里的先出现者，因而结果可复现。缺精确组合时取声学上最近的真实录音，
而不是拼接——这正是 MUTA "换采样"能力的来源。左/右上下文用相邻音符的音素，
`BankLeft` 用于模型没有声母时（例如 ん 走 bank 的「恩」，左邻固定为 `ge`）。

### 5.5 基频（F0）

两条规则，逐帧决定目标：

| 条件 | 行为 |
|---|---|
| 用户画了音高线（`Pitch` 该帧有值） | **该帧 F0 直接取绝对 MIDI**，不经过钳制与滑音 |
| 没画线（NaN） | 模型 LF0 作载波，按音符弯折：截尾均值对齐、±0.22 半音钳制、起音斜坡、连音延伸；相邻不同音高时，滑音跨边界（边界前 90 ms 起、后 30 ms 落，半音域 smoothstep） |

`PitchDeviation`（颤音、手画的偏差）两条路径都叠加。
回显与音频共用同一份逐帧 F0，所以"看到的"就是"听到的"。

宿主音高线是**绝对音高**，且锚点之间是 **smoothstep（ease-in-out）** 而不是线性——
拿线性去对会得到"差一个半音"的假象，实测四个采样点与 `3x²−2x³` 逐位吻合。

### 5.6 参数与频谱

| 参数 | 作用点 |
|---|---|
| Energy | 帧对数增益（`mgc[f][0] += dB·ln10/20`） |
| Timbre | 频谱弯折因子 α（按 0.005 分桶，一次 FFT 覆盖同桶帧） |
| Husky | 非周期性（`bap[f][b] += dB`） |
| Gender / Tension / Breathiness / Voicing | 逐帧数组直传声码器 |
| phoneme_speed | HTS 的 speed |
| bank_pitch_offset（音符级） | **只决定选哪段录音**，不参与 F0 |
| output_gain_db | 软限幅前的线性增益 |

不画曲线时参数为空，渲染结果与不接线逐样本一致。

频谱侧：MGC 经 α 弯折后 FFT 成 1025 点功率谱；BAP 展开成每 bin 的非周期性权重。

### 5.7 声码器与输出

- **R1.1**（默认）：worldline 的连续噪声模型，噪声在时域生成，没有帧边界调制；
- **R2**（可选）：先用 `mel.onnx` 求 mel 谱，再交给用户自备的神经声码器；
  Windows 走 DirectML，Linux/macOS 走 WebGPU，取不到就回退 CPU。

**换气**在声码器之后混入：换气音符对声学模型是休止（中文 `sp`、日文空拍），
`BreathRenderer` 从 `.inf` finals 取一段连续窗口（无 finals 用 1.6–8 kHz 带通噪声），
做 500 Hz 高通 + 2.5 kHz 高架、30 ms 起音与尾部衰减，归一化后按同块演唱 RMS 的
0.224 倍（−13 dB）加进输出；它不参与 F0，音高曲线无效。

输出：静音门（带短斜坡，避免休止处的"很轻的噪声"）→ 声码器参数跳变处的短凹陷 →
软膝限幅（**0.8 起膝、0.9 封顶**）。封顶是 0.9 而不是 0.95：宿主导出时 48k→44.1k 重采样对
饱和信号有几个百分点的过冲，0.95 实测回到 0.9988，几乎满刻度。

## 6. 音素几何与回显

- 几何交给宿主自己的 `PhonemeLayout.Resolve`：插件只构造 `PhonemeLayoutNote`
  （填充范围、leading/body 双列表、`BodyOffset`），宿主返回绝对时间。
  这样"听到的"和"看到的"用同一份排布逻辑。
- `BodyOffset` = 声母时长，让辅音落在音符内部（MUTA 语义）。
- 音高回显：逐帧 F0 → `(秒, 半音)` 折线，20 ms 抽稀。回显与音频用同一份 F0，但显示前会
  把**有声材料内部** ≤250 ms 的无音高洞（清辅音、carrier 空洞）用对数线性插值补上；真休止
  （`silence` 为真）仍然断开。这样编辑器不会在每个辅音处看到断线，而音频的 UV 不受影响。

**钉死音素**：快照里 leading/body 任一非空即用户钉死，几何原样上报（多 leading、多 body 都保留）；
中文按钉死重拼拼音音节，日文按假名表反查（`k`+`y`+`a` → きゃ）。没钉死的音符走原路径。

**连音**：歌词 `-` 或 `+`、沿 `Previous` 回溯到内容 note、沿途相接 → 乘客 note，
不发音素、不选槽；链头的韵母在标签、bank 与几何里都覆盖整段（`FillEnd` 铺过乘客），
宿主拿到的乘客音节是零音素。孤儿 `-` 退化成裸元音；块首孤儿按内容唱。
`+` 与 `-` 同义是插件扩展（宿主本身只把 `-` 当延音），这样 MUTA 的连音听感才成立。
**换气**：`br`（同义 `sp`）对标签是 `sp` 停顿 / 日文空拍，宿主可见音素是 `sp`，
音频由 `BreathRenderer` 在声码器之后叠加。

## 7. 分块、缓存与确定性

- 分块规则：间隔 > 0.4 s、或跨度 > 12 s、或音符数 > 240 即断开；
  渲染器另设 12000 帧（60 s）硬上限，超限的块失败而不是进入原生分配；
- 边界落在两段之间的静音中点（间隔 ≤ 1 s），否则前后各留 50 / 150 ms；
- 块签名 = 音符数据 + 曲线版本 + part 属性，任一变化即重渲；
- 曲线改动靠订阅 `RangeModified` / `Modified` 递增版本号，不比对采样值；
- 声码器噪声种子由 `(音源 id, 块起始时间)` 经 FNV-1a 派生：同块可复现，块间不同；
- 已完成的块缓存音频段与音素，编辑只重渲受影响的块。

**失败可见**：音素对齐校验（标签实际给出的音素序列 vs 前端预期）不一致时，该块标记 Failed、
拒绝导出，并在状态里写明"第几个音符期望 N 个音素、标签给了 M 个"，绝不静默平移。

## 8. 原生库、跨平台与打包

三个原生库由 `tools/build-native.ps1` 用 MSVC 编译，随包分发：

| 库 | 作用 |
|---|---|
| `muta_hts.dll` | HTS engine 包装 |
| `worldline.dll` | WORLD 声码器（OpenUtau 的 worldline） |
| `muta_sinsy.dll` | Sinsy 标签前端（含音素表与 NIT 模型） |

ONNX Runtime 按平台选择：

| 平台 | 包 | EP |
|---|---|---|
| Windows | `Microsoft.ML.OnnxRuntime.DirectML` **1.23**（1.24 在部分驱动上会卡死） | DirectML，失败回退 CPU |
| Linux / macOS | `Microsoft.ML.OnnxRuntime` **1.31** | WebGPU，取不到回退 CPU |

发布两个包：

- **完整版**（19.9 MB）：R1.1 + 可选 R2 + ONNX Runtime；
- **便携版**（4.9 MB，`-p:MutaLite=true`）：不引 ORT、不带 `mel.onnx`、不编译 R2 实现，
  R2 也从设置与模式解析里隐藏。

CI：`.github/workflows/build.yml`，unit → 三平台矩阵 → tag 触发 prerelease。
Windows 是已验证目标；Linux/macOS 的原生库仍需移植（TuneLab 官方也未构建这两个平台）。

## 9. 测试与验收

| 层 | 数量 | 覆盖 |
|---|---|---|
| 单元（`tests/UnitTests`） | 40 | 映射表、中文/日文前端、标签解析、时间轴、F0、bank 装配（假 bank）、选槽、音节拆分、假名反查 |
| 集成（`tools/parameter-sweep.ps1`，TuneLab CLI） | 26 | 7 条自动化两端、bank 音区、音高线、语速、1 tick 音符、MIDI 0/127、长休止、颤音、多块 |

单元测试不引 SDK、不引 NuGet：直接编译纯逻辑源码，CI 里只靠 .NET SDK 就能跑。
集成测试跑真实宿主：建工程 → 导出 → 用 `tools/wav-stat.py` 检查峰值/RMS、用 `tools/f0-track.py`
测量实际 F0。

几个用测量定下来的数字：

- 颤音 0.5 半音 / 6 Hz → 单音内 F0 标准差 0.278 半音、范围 0.908；
- 60→72 的斜坡 → 逐帧 F0 与曲线逐点相同（`60.73 / 61.88 / 66.00 / 70.13` = smoothstep）；
- +24 dB 的 energy → 峰值 0.953（限幅 0.9 生效，无满刻度样本）。

## 10. 已知限制

- bank 没有干净的 `[o]`（只有 b/p/m/f 后的 w 过渡）、没有 `k|i`、`uo` 缺 m/b/p/f；
- `きゅ` 的 `iu` 带 u 尾、`きょ` 的 `iao` 带 ao 尾——试听定稿接受的上限；
- 模型 F0 作载波时，`F0Mechanism` 的 ±0.22 钳制会在音符内部把它抹平，实际只在音符边界起作用；
- `+` 的一词多音节切分未实现（宿主逐 note 罗马化时不会出现）；
- 整曲规模（中文 259 / 日文 540 音符）尚未做验收。

## 11. 工程经验

1. **先测量，再改。** 音高"差一个半音"最后是测试假设错了（宿主用 ease 曲线）；日文短句少音素
   最后是音符被小节线切开。两次都是先打印证据（逐帧探针 / 生成的 XML）才定位。
2. **别猜宿主 API。** 钉死音素的字段、连音的 `-`/`+` 语义都写文档里；猜出来的签名会"测试通过但测的是空气"。
3. **合成的每一步都要能解释。** bank 选槽、F0 钳制、限幅上限，每一项都有实测数字支撑。
4. **失败要响。** 对齐不一致时拒绝导出并给出音素序列，比静默平移好——后者会把人声悄悄错位。

## 12. 关键决策一览

| 决策 | 理由 |
|---|---|
| 语言是 part 属性、无 auto | 宿主已罗马化，文本无法区分 `ni` 属于哪种语言 |
| 日文不设独立声源 | 日文只需前端与标签，音色本来就该来自 bank |
| 音高线逐帧绝对 | 非生成式引擎应对用户编辑绝对忠诚；未编辑处才用模型手感 |
| bank 只跟音符音高 | 拖曲线时音色稳定；要换音区就显式改设置 |
| 映射表是运行时数据 | 按试听定稿，改表不该重新编译 |
| 便携版去掉 ORT | 大多数用户只需要 R1.1，省 15 MB 且没有 GPU 驱动风险 |
| 限幅 0.9 | 给宿主的重采样留过冲余量 |
